# NC-004 Execution Plan

**State:** Completed — Review Gate A approved on 2026-08-09

## Objective

Implement a deterministic, explainable, versioned Relationship Engine that derives one normalized `RelationshipProfile` per observed person pair from canonical fact data without FastAPI, database, or infrastructure coupling.

## Scope

- immutable `RelationshipProfile`, `RelationshipContext`, and `EvidenceCoverage` domain types
- versioned `relationship-v0.1.0` configuration for type/duration weights, decay, saturation, boosts, cadence, and state thresholds
- event evidence using `B * G * D * C * T`
- digital/analog component saturation, historical depth, bounded context, reciprocity, channel diversity, strength, cadence, dormancy, reconnection, and data confidence
- single-pair and bulk normalized-pair derivation
- synthetic validation of P001 mixed states, P018 DORMANT, and P102 RECONNECTED
- pure domain and synthetic integration tests for every NC-004 edge case

## Decisions

- The engine is pure Python domain logic and has no dependency on FastAPI, Pydantic, SQLAlchemy, NetworkX, or persistence.
- Numeric calibration omitted by the frozen conceptual specification is isolated in immutable versioned configuration and documented for Review Gate A.
- Context can only boost a profile after direct event evidence exists; context alone returns no relationship.
- Evidence collection coverage affects `dataConfidence` only. Missing analog coverage never directly reduces strength or state.
- Unknown reciprocity receives no boost and no penalty. Known balanced directional evidence receives a small bounded boost.
- A lower median of distinct interaction intervals makes cadence robust to duplicate timestamps and a single long dormant gap.
- Large-group co-presence remains traceable but receives minimal group/type/confidence evidence.
- User-feedback kinds and formula effects remain deferred because the frozen model does not define their semantics; raw facts are never rewritten.

## Acceptance mapping

- AC-B01/02: canonical `InteractionEvent` values derive profiles through a standalone domain service
- AC-B03: digital-only and analog-only fixtures both derive CLOSE
- AC-B04: P001/P018 derives DORMANT
- AC-B05: P001/P102 derives RECONNECTED from old cadence plus recent coffee
- AC-B06: shared community/activity without interaction derives no profile
- AC-B07/08: every profile retains model version and bounded data confidence
- AC-B09/10: `PersonPair` rejects self-pairs and bulk derivation emits one canonical pair profile
- critical model cases: large-event evidence remains minimal; missing analog lowers confidence only; reciprocity and event confidence are explainable components

## Deferred

- Persistence/materialization and rebuild commands belong to NC-005.
- Graph projection and API serialization belong to NC-006/NC-007.
- User correction kinds/payloads require a frozen semantic specification before formula integration.
- Any calibration change after Review Gate A must use a new model version rather than silently changing v0.1.0.

## Review Gate A decision

- Review Gate A completed on 2026-08-09; the documented `relationship-v0.1.0` behavior and calibration were accepted.
- User-correction evidence kinds, payloads, and numeric formula effects remain intentionally deferred to a later frozen specification.
- A later user-correction specification must preserve source facts and introduce a new model version for any calibration change.
