# NC-006 — Network Projection Service

**State:** Completed — Review Gate B approved on 2026-08-09

## Objective

Implement a deterministic, current-user-specific `GraphProjection` over materialized
`RelationshipProfile` data. The default projection contains one focal person, at most 24 direct
people, and at most 12 two-hop teaser people. A selected-person expansion adds at most eight people
without exceeding the hard visible limit of 80. Produce a reviewable P001 JSON artifact and stop at
Review Gate B; NC-007 API endpoints and NC-008+ UI behavior remain out of scope.

## Files and boundaries

- Add pure projection read models, versioned configuration, candidate relevance, NetworkX traversal,
  diversity-aware sampling, cluster assignment, presentation buckets, and expansion behavior under
  `services/api/app/domain/`.
- Add an application query service under `services/api/app/application/` that accepts an already
  authorized current-person ID and reads people, organization units, and materialized relationship
  profiles through protocols.
- Extend the SQLAlchemy fact repository only with the organization-unit read needed by the query
  service; reuse the existing people and relationship-profile reads. No migration is required.
- Add a P001 review command and Make target. The command reads the persisted demo facts/profiles and
  emits an envelope containing the production-shaped projection, synthetic-ID lookup, composition,
  bound checks, path checks, and privacy checks. Commit the deterministic artifact under
  `docs/review-artifacts/`.
- Add NetworkX as the approved graph-computation dependency and update the locked environment.
- Add domain, application, persistence/command integration, privacy, determinism, and P001 fixture
  tests. Update repository status/navigation and projection documentation after verification.

## Projection and sampling choices

- Treat every materialized `RelationshipProfile` as an observed graph edge; context-only facts never
  create an edge.
- Compute direct relevance from current activation, historical depth, relationship strength, data
  confidence, recency, and a bounded state-specific memory utility. Career level, seniority,
  centrality, degree, and relationship count are not inputs.
- Select one best direct candidate from each available relationship state, then one from each
  available organization cluster, then fill with deterministic maximal-marginal-relevance sampling.
  This makes dormant/active and cross-organization composition explicit instead of taking the top
  relationship strengths.
- Generate teaser candidates only at NetworkX shortest-path distance two. Rank by focal-to-mutual
  accessibility plus organization novelty; mutual count is reported as context but is not a ranking
  feature. Retain at most three deterministic shortest paths per teaser.
- Organization units are soft cluster metadata attached to person nodes, never graph nodes or hard
  containers. People without a primary organization use an `unassigned` cluster.
- Direct focal edges may carry the focal user's relationship metrics and presentation buckets.
  Third-party path edges carry only endpoint IDs, `POTENTIAL_PATH`, and muted presentation semantics.
- Expansion preserves every existing node/edge and deterministically adds up to eight still-hidden
  neighbors whose shortest distance from the focal person is at most two. The total never exceeds
  80 nodes.

## Privacy boundary

The application service is a personal-graph use case: callers supply only the authenticated current
person's own ID, and there is no administrative/person-ID endpoint in NC-006. Visibility enforcement
occurs before serialization. The projection contains identity facts for selected people, focal-relative
metrics only on direct edges, and minimal person-ID paths for two-hop people. It never serializes
third-party relationship state, strength, activation, event history, private activities, or arbitrary
third-party context.

## P001 review JSON

Reset the deterministic demo dataset, resolve `synthetic/P001`, query the same application service
used by a later API boundary, and write canonical pretty JSON. A review-only synthetic-ID lookup makes
P018/P067 and path composition human-auditable without adding synthetic identifiers to the production
read model. `generatedAt` comes from the persisted relationship calculation timestamp so equivalent
facts produce byte-identical output.

## Assumptions and stop condition

- NC-006 defines the internal read model and service, not the final Pydantic/OpenAPI schema; NC-007 owns
  `/api/v1/me/network` and development-persona authentication.
- Expansion is limited to the same two-hop personal neighborhood. Deeper traversal would exceed the
  accepted MVP scope and requires a later specification.
- Position preservation is a frontend/session concern; NC-006 preserves projection membership and
  ordering but does not calculate Sigma coordinates.
- Stop after publishing the implementation and P001 artifact for Review Gate B. Do not begin NC-007.

## Completion evidence

- `graph-projection-v0.1.0` implements pure read models, NetworkX distance-two traversal, direct and
  teaser candidate relevance, state/organization diversity sampling, shortest paths/mutuals, soft
  organization clusters, focal-relative presentation buckets, and bounded expansion.
- P001 persists 40 direct relationships and 52 additional reachable two-hop people; the default
  projection deterministically samples 24 direct + 12 teaser people for 37 visible nodes from a
  92-person two-hop network.
- The default contains CLOSE 8 / ACTIVE 13 / WEAK 1 / DORMANT 1 / RECONNECTED 1 direct states,
  includes Technology / AI & Data and Strategy clusters, keeps P018 as DORMANT, and includes P067 as
  potential through `P001 -> P010 -> P067`.
- Third-party `POTENTIAL_PATH` edges contain only endpoint and muted presentation fields; state,
  strength, activation, evidence, activities, and career/seniority/ranking fields are absent.
- Expansion adds at most eight new nodes, preserves the existing node/edge prefix, is idempotent per
  selected person, remains within distance two, and never crosses the hard 80-node limit.
- `make check` passes with Node.js 24, pnpm 10.34.5, and Python 3.13: Prettier, ESLint, Ruff, strict
  mypy (59 source files), Vitest (1 test), pytest (70 tests), and the Next.js production build.
- `make projection-review-p001` upgrades PostgreSQL, resets canonical demo facts, rebuilds 535
  relationship profiles, and writes `docs/review-artifacts/NC-006-p001-graph-projection.json`.
  Two complete reset/render executions are byte-identical at SHA-256
  `c80cba65265364413d415fd263d73653b3f125dd933ae4f8c5290e454a22a172`.
- `uv lock --check`, `docker compose config --quiet`, `alembic check`, the container database
  connection check, and `git diff --check` pass. No migration, product API, authentication, frontend
  graph, recommendation, or user-feedback formula behavior was added.
