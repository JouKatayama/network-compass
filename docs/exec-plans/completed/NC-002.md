# NC-002 Execution Plan

**State:** Completed — human-reviewed, CI-verified, and merged on 2026-08-09

## Objective

Implement the canonical fact-domain vocabulary and interaction-event invariants needed by later synthetic-data, relationship-engine, persistence, and API work without implementing those later features.

## Scope

- pure Python enums for the explicitly specified canonical values
- immutable domain value objects for canonical UUIDs, normalized external identifiers, normalized person pairs, UTC timestamps, and bounded confidence
- immutable fact entities named by the canonical domain model
- immutable `InteractionEvent` with participant, provenance, confidence, context, and timestamp validation
- strict Pydantic boundary schemas and conversion into domain objects
- domain-focused pytest coverage

## Decisions

- Domain objects use frozen, slotted dataclasses and do not depend on FastAPI, Pydantic, SQLAlchemy, or infrastructure code.
- Pydantic schemas live under `app/models` and use camelCase aliases with unknown fields rejected.
- No SQLAlchemy mappings, migrations, API routes, relationship formulas, recommendation logic, graph models, or generated frontend contracts are introduced in NC-002.
- Context entities receive only identity, linkage, visibility, and lifecycle fields justified by the frozen specifications. Unspecified business taxonomies are not invented.
- `UserRelationshipFeedback` records an immutable normalized pair and authorship metadata only; feedback kinds, payloads, and formula effects remain deferred because the frozen specification does not define them.

## Invariants to verify

- internal IDs are UUIDs and external identifiers are separate, trimmed mappings
- person pairs have deterministic UUID order and reject self-pairs
- stored/API datetimes are timezone-aware and normalized to UTC
- interaction participants are unique and contain at least two people
- conversation participant count cannot be smaller than the recorded participant set
- confidence is within `[0, 1]`
- external event provenance fields appear together
- self-reported analog events identify the reporting participant
- user-declared activity visibility is carried by the person-activity fact

## Deferred specification questions

- Feedback kinds and their relationship-engine semantics are not defined in v0.1 documents.
- Detailed persistence columns and uniqueness constraints remain owned by NC-005.
- Derived/read-model shapes remain owned by NC-004, NC-006, and NC-007.
