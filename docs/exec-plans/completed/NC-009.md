# NC-009 — Person Detail + Graph Interaction

**State:** Completed — Review Gate C approved on 2026-08-09

## Objective

Complete the accepted My Network interaction layer over the NC-008 graph foundation: hover and
selection, current-person-relative Person Detail, structured people search, bounded server-side
expansion, potential-path emphasis, and accessibility alternatives. Validate the deterministic
P001→P018→P067 hero journey and stop for Review Gate C.

## Files and boundaries

- Extend the network and people API boundary only as required for authenticated graph expansion.
  Keep the existing no-input `GET /api/v1/me/network` contract unchanged.
- Add same-origin Next.js proxies and generated-type consumers for person detail, people search, and
  expansion. The browser never sends an arbitrary focal-person ID.
- Keep React interaction state under `apps/web/features/network/`; keep graph transforms, local
  expansion layout, reducers, hit handling, and camera control under its `graph/` subsystem.
- Do not add recommendations, interaction writes, contact actions, global People pages, Network
  Health, Network Ramp, production SSO, or NC-010 completion behavior.

## Expansion API contract

- Add `POST /api/v1/me/network/expand` with the selected visible person ID and the ordered list of
  previously expanded visible people. Rebuild the current user's accepted projection server-side,
  replay the bounded expansion history, and apply the requested expansion.
- Reject an invalid, duplicate, or non-visible expansion history. Do not accept a client-supplied
  focal ID or GraphProjection payload.
- Reuse `NetworkProjectionService.expand`: each new action adds at most eight authorized people,
  never exceeds the hard visible limit of 80, and exposes only the existing privacy-safe projection
  serialization.

## Interaction and mental-map choices

- Sigma owns node hit detection. React owns hover summary, selection, search results, drawer state,
  expansion feedback, and accessible announcements.
- Selection emphasizes the selected person's known incident edges/neighbors. Potential selection
  emphasizes only the bounded connection path returned by Person Detail; unrelated context fades
  without disappearing or being re-laid out.
- Preserve all existing coordinates exactly on expansion. Place only new nodes near the selected
  node using deterministic seeded angles and bounded local collision relaxation. Preserve the Sigma
  camera across graph-model replacement; minimal focus pan is allowed for search selection.
- Hover shows a concise factual identity/relationship summary. It must not expose numeric scores or
  become the only way to select a person.

## Search and Person Detail

- Provide a labelled keyboard-operable search combobox with bounded, debounced results. Selecting a
  visible result focuses/selects it; a non-visible result opens the same factual detail route and
  adds only its permitted minimal path context when the path can be anchored to a visible node.
- The drawer implements loading, connected, potential, limited-history, and safe retryable error
  states. Esc and the visible close control close it without changing graph coordinates/camera.
- Show identity, natural-language relationship label, last contact/known duration when present,
  factual timeline, permitted shared context, mutual connections, and bounded connection path.
  Potential detail prioritizes `まだ直接話したことはありません` and never invents a timeline.
