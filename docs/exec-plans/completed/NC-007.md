# NC-007 — API v0.1

**State:** Completed — human-reviewed and merged on 2026-08-09

## Objective

Expose the accepted personal-network projection and the frozen VS001 person-detail/search read models
through FastAPI under `/api/v1`. Resolve the current person at the server boundary, enforce activity
and relationship-context visibility before serialization, publish a checked-in canonical OpenAPI
contract, and stop before NC-008 graph UI work.

## Endpoints and schemas

- `GET /api/v1/me/network` returns the existing `GraphProjection` with one focal person, at most 24
  direct people, and at most 12 two-hop teasers. The v0.1 endpoint has no expansion inputs; selected
  expansion remains available internally for the later NC-009 interaction contract.
- `GET /api/v1/people/{personId}` returns current-person-relative identity, a natural-language
  relationship summary, factual timeline, permitted common context, and a minimal connection path.
  It never returns the numeric relationship score or arbitrary third-party relationship metrics.
- `GET /api/v1/people/search` supports bounded text search, opaque cursor pagination, and optional
  organization/community/activity/skill UUID filters. Results carry only direct/two-hop/none context
  and permitted bounded common context.
- Pydantic response models use camel-case aliases and explicit error schemas. FastAPI's generated
  OpenAPI document is canonical and is checked into `packages/contracts/openapi.json`; CI fails when
  implementation and artifact drift.

## Current-user authorization and errors

- Resolve a development persona from an allowlisted synthetic external identifier such as `P001`,
  supplied by `X-Network-Compass-Persona` or a configured development default. Never accept an
  arbitrary current-person UUID from a client.
- Enable persona switching only in development/test. Production mode rejects unauthenticated reads
  with the standard safe error envelope until the later production SSO integration exists.
- Attach a `req_...` request ID to every response and convert domain, validation, routing, and
  unexpected failures to `{ "error": { "code", "message", "requestId" } }` without internal detail.
- Keep CORS restricted to configured origins and wire database sessions through an app factory so
  API integration tests do not depend on global state.

## Person detail, search, and privacy

- Add a pure application query service over repository protocols for people, organizations,
  relationship profiles, interactions, communities, activities, skills, and projects. For VS001,
  each request reads the bounded demo snapshot; query-level optimization is deferred.
- Derive direct, two-hop, none, and self context from observed relationship profiles. Two-hop detail
  carries only a bounded shortest person path and factual common context; it does not expose metrics
  for relationships between other people.
- Render `DORMANT` as `久しぶりのつながり`. Potential detail uses
  `まだ直接話したことはありません`, prioritizes the connection path, and has no fabricated
  timeline.
- Enforce activity visibility on the server: private declarations belong only to their declaring
  person, network declarations require a direct relationship, and organization declarations require
  the current and target people to share the primary organization. Apply the same rules to detail,
  search text, filters, and common context.
- Order search deterministically without career level, seniority, centrality, degree, influence, or
  relationship-count ranking. Bind opaque cursors to the complete search criteria.

## Assumptions and stop condition

- The existing `graph-projection-v0.1.0` algorithm and accepted sampling behavior are unchanged;
  NC-007 adds an authorization/schema boundary around it.
- A no-parameter network endpoint is the final VS001 default contract. Expansion/query fields are
  optional future-compatible ideas, not required frozen v0.1 behavior.
- Production SSO, recommendations, user-feedback formula changes, frontend API consumption, graph UI,
  and NC-008+ behavior remain out of scope.
- Stop after publishing the implementation for human review; do not begin NC-008.

## Completion evidence

- Implemented exactly the three VS001 product reads under `/api/v1`: personal network, person detail,
  and structured people search. No recommendation, feedback, interaction-write, Network Ramp, home,
  or graph-UI endpoint was added.
- Development/test current-person resolution uses persisted synthetic external IDs with a `P001`
  default and optional `X-Network-Compass-Persona`; production disables the mechanism and returns the
  safe `AUTHENTICATION_REQUIRED` envelope. Clients cannot submit an arbitrary current-person UUID.
- Person detail returns natural-language state, factual direct-event/shared-project timeline, common
  context, and bounded paths without numeric relationship metrics. P018 returns
  `久しぶりのつながり` plus one factual shared project; P067 returns the P001→P010→P067 path and
  an empty timeline.

  activity/skill filters. Private/network/organization activity visibility is enforced before search
  matching, filtering, detail common context, and serialization.
- Every handled error uses the frozen envelope and `req_...` ID; validation, not-found, invalid cursor,
  authentication, and unexpected-error paths are covered. Unexpected errors are logged server-side
  while client responses omit internal detail. CORS permits only configured origins.
- FastAPI generates `packages/contracts/openapi.json`; `make openapi-check` is part of `make check`
  and the backend CI job. The artifact contains health plus exactly the three NC-007 product paths.

## Remaining risks and deferred work

- Production SSO is intentionally absent; production product reads remain closed with 401 until the
  later authentication integration supplies an authorized current person.
- The application read service loads the bounded VS001 demo snapshot per request. SQL-level search,
  selective eager reads, and cache/performance work are deferred until scale evidence requires them.
- NC-008 must generate frontend types from the checked-in OpenAPI contract. It must not hand-copy
  these schemas or reinterpret server-side visibility rules.
