# NC-008 — Frontend Shell + Graph Foundation

**State:** Implemented and verified — awaiting Human UI Review

## Objective

Implement the accepted `/network` foundation over the NC-007 personal-network API: generate
TypeScript types from the canonical OpenAPI artifact, transform `GraphProjection` into a person-only
Graphology graph, calculate stable cluster-aware coordinates, render it with Sigma.js, and provide
camera controls plus complete loading/normal/empty/error states. Produce a human-reviewable P001
screen and stop before NC-009 interaction work.

## Files and boundaries

- Replace the NC-001 foundation page with a single-purpose My Network shell and `/network` route.
  The root route may redirect to `/network`; do not create placeholder product areas.
- Add the approved Sigma.js, Graphology, and TanStack Query dependencies. Keep graph transformation,
  layout, camera, and overlay code in `apps/web/features/network/graph/`, not page components.
- Add a checked-in, reproducible OpenAPI-to-TypeScript generation step. Frontend request code must
  consume generated types and must not duplicate backend schemas or visibility rules.
- Use TanStack Query for the `/api/v1/me/network` server state. Keep zoom, hop visibility, and other
  presentation-only state local to the graph feature.
- Use CSS semantic design tokens and responsive layout. Organization/community data remains soft
  visual context and never becomes a fake graph node or hard territory.

## Projection and layout choices

- Add only `PERSON` projection nodes to Graphology. Add direct relationship and potential-path
  projection edges without synthesizing edges or recalculating relationship measures.
- Map backend presentation buckets directly: node relevance controls a narrow size range; direct edge
  width follows strength; opacity follows activation; dormant edges are dashed and lower opacity;
  potential/two-hop edges are dotted or muted. Never map seniority, career level, centrality, degree,
  influence, or relationship count to prominence.
- Initialize each person from a stable hash of person and primary-cluster identifiers, then run a
  fixed-count deterministic force pass with focal gravity, edge attraction, node repulsion/collision,
  and soft cluster attraction. Normalize the result with the focal person at the origin.
- Preserve the computed coordinate map for the component session. Camera changes must not trigger a
  layout pass; equivalent inputs must produce equivalent coordinates.
- Draw translucent, non-interactive organization regions behind the person graph. Missing/unassigned
  organization context uses a neutral treatment rather than a negative signal.

## Shell and screen states

- Make the graph the dominant working surface (approximately 65–75% of the viewport) with a concise
  My Network header, graph-count/context status, accessible legend, and visible Zoom in, Zoom out,
  Fit, and Center on me controls.
- Sigma handles node/edge rendering, camera, pan, zoom, and hit detection. React owns the shell,
  controls, state feedback, legends, and organization overlay layer.
- Render bounded skeleton/loading, safe retryable error, and neutral empty states. Do not expose raw
  backend error detail. Provide meaningful accessible text outside WebGL so the graph is not the only
  path to understand current state.
- A local 1-hop/2-hop visibility control may filter the already-authorized projection; it must not
  request expansion or imply that the NC-009 detail/path interaction is implemented.

## Excluded NC-009 behavior

- Do not implement person hover cards, selection state, search-driven selection, Person Detail
  drawer, connection-path emphasis, node expansion, keyboard person picker, or coordinate preservation
  across an expansion. The Sigma subsystem may expose minimal internal hit/camera seams needed for
  later work, but no user-facing incomplete interaction should appear.

## Assumptions and stop condition

- NC-007's no-parameter `/api/v1/me/network` response and server-side visibility enforcement are
  accepted. The frontend sends no arbitrary current-person UUID; local development uses the API's
  accepted P001 default persona.
- The deterministic frontend layout is a presentation baseline, not a new projection-ranking model.
  Calibration changes do not change API membership, score people, or reinterpret missing data.
- Full semantic zoom behavior may hide labels at lower zoom while retaining person nodes and edge
  context; a card-wall or 3D/particle graph is out of scope.
- Human UI Review is mandatory. Stop after publishing the implementation and review artifact; do not
  start NC-009 until the reviewer accepts NC-008.

## Completion evidence

- `/` redirects to the single My Network `/network` surface. The responsive Japanese shell provides
  privacy context, 1-hop/2-hop visibility, visible-person counts, a non-canvas legend, and accessible
  Zoom in, Zoom out, Fit, and Center on me controls without adding placeholder product areas.
- The checked-in NC-007 OpenAPI contract generates TypeScript-only artifacts through pinned
  `@hey-api/openapi-ts`. `make check` regenerates and rejects tracked output drift before the frontend
  production build.
- TanStack Query reads the current personal projection through a same-origin, server-only Next.js
  proxy. The browser never submits a person UUID or reimplements visibility; upstream API errors stay
  safe and the screen exposes loading, neutral empty, retryable error, and normal states.
- Graphology contains only the 37 P001 person nodes and accepted projection edges. A fixed 180-pass,
  input-order-independent layout keeps the focal person at `(0, 0)`, applies edge/cluster attraction
  and collision/repulsion, and reuses the full-projection bounding box across hop filtering.
- Sigma.js provides WebGL person rendering, hit detection, pan/zoom, and camera control. Sigma-bound
  Canvas layers draw accepted width/opacity plus solid/dashed/dotted edge semantics and translucent,
  non-interactive organization regions; organizations are never graph nodes.
- Desktop and 390px mobile views were inspected in the in-app browser. The range toggle moved from
  37 to 25 and back to 37, all camera controls responded, and the final fresh browser tab emitted no
  errors or warnings. Small screens suppress long non-focal labels while retaining accessible state.
- The deterministic P001 Human UI Review artifact is
  `docs/review-artifacts/NC-008-p001-network.png`, SHA-256
  `cebaad19d98c95cdf890c34915b5ff2a8a47f181224acfd6600ea73ca524d4a5`.
- `make check` passes on Node.js 24/Python 3.13: Prettier, ESLint, Ruff, strict TypeScript and mypy
  (72 Python source files), Vitest (8 tests), pytest (78 tests), OpenAPI and generated-TypeScript
  drift checks, and the Next.js production build.
- Docker Compose built and served the stack after a `demo-v0.1.1` reset containing 250 people and
  535 relationship profiles. Playwright passed the P001 `/network` shell/37-person/control smoke and
  API health tests. `uv lock --check`, `docker compose config --quiet`, and `git diff --check` pass.
