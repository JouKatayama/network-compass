# NC-003 Execution Plan

**State:** Implemented and ready for human review

## Objective

Generate deterministic synthetic fact datasets and explicit scenario expectations for demo and relationship-engine edge-case development without generating derived relationship state.

## Scope

- additive fact fields required by the frozen synthetic specification: person role/career level/location/avatar and interaction initiator
- deterministic `demo` dataset with exactly 250 synthetic people and the specified organization composition
- compact `edge_cases` family containing every required fixture
- P001/P201/P202 primary personas and P018/P067/P102 hero scenarios
- fixed seed, dataset version, fixed reference time, stable UUIDs, and stable JSON ordering
- JSON dataset, summary, scenario manifest, and validation report output
- CLI and Make targets for reproducible generation
- unit tests for reproducibility, composition, invariants, paths, and edge-case coverage

## Decisions

- Generated identities use obvious synthetic labels and reserved `.invalid` avatar URLs; no real employee data or unnecessary sensitive attributes are used.
- Facts use the canonical domain dataclasses from `services/api`; generator models do not duplicate relationship state or API schemas.
- `initiatorPersonId` is optional and, when present, must identify an event participant. It distinguishes one-sided and reciprocal digital fixtures.
- Relationship-state expectations live only in the scenario manifest. NC-004 checks them against derived output; NC-003 reports those checks as `PENDING_NC_004`.
- The demo uses exact organization counts `80/35/45/30/20/25/15`, 25 recent joiners, deterministic within-unit ties, and explicit cross-unit bridges.
- Generated output is reproducible build data and is ignored by Git; tests compare canonical serialized bytes.

## Acceptance mapping

- AC-S01: same seed/version produces byte-identical canonical JSON
- AC-S02/03: 250 people and seven organization clusters with specified counts
- AC-S04: P001 has exactly 40 distinct meaningful-interaction counterpart candidates
- primary-persona topology: P001 has 52 people at exactly two hops, P201 has a shared cohort/community/project network, and P202 has rich professional context with only three direct counterparts
- AC-S05/06/07: expected state patterns exist in the scenario manifest; derivation remains pending NC-004
- AC-S08/09: P067 has no direct P001 event and has the explicit P001 -> P010 -> P067 path
- AC-S10: validator rejects any interaction before a participant's `joinedAt`
- AC-S11: CLI writes validation and summary JSON

## Deferred

- Relationship formulas, derived profiles, and expectation comparison are owned by NC-004.
- Database loading/reset is owned by NC-005.
- Stress-family generation remains later scope as specified.
